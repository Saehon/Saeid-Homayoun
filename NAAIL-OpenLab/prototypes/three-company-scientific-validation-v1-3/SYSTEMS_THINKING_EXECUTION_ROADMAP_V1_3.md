**Date:** 2026-09-17  
**Artifact type:** execution governance / orchestration  
**Maturity:** `RESEARCH_PROTOTYPE`  
**Scientific-status effect:** none by itself  

> **PATENT RIGHTS RESERVED — PATENT APPLICATION PREPARATION IN PROGRESS**

## Purpose

This roadmap breaks the remaining V1.3 work into small, auditable gates. Each gate must produce its own evidence, status decision, GitHub artifact and Google Drive mirror before the next gate is treated as eligible for execution. The presence of a design file never counts as execution.

The frozen NAAIL constitution remains unchanged: exactly two permanent cores — Stable Knowledge Core™ and Replaceable Technology Core™ — with the 3-company × 20-step contract for Microsoft (`MSFT`), Walmart (`WMT`) and JPMorgan Chase (`JPM`). Failed, null, contradictory, blocked and sensitivity-dependent evidence must remain visible. Patent-sensitive enabling material remains private until filing review.

## Current boundary

The existing Phase 1 materials are treated as read-only context in this execution sequence. This roadmap does not rerun Phase 1 and does not infer any new Human Gate or independent-replication outcome from those artifacts.

The next scientific target is **Phase 2 — Blind Professional AI Benchmark & Verified Cost**, but it is divided into independent work packages below.

## Stage 0 — State Lock & Cross-Repository Baseline

**Goal:** freeze the working assumptions before new scientific execution.

**Required checks:**
- preserve the two-core constitution;
- preserve the 3 × 20 execution contract;
- preserve scientific-status vocabulary;
- preserve the patent-first public/private boundary;
- preserve negative, null and contradictory evidence;
- preserve WMT/JPM Human Gate restrictions;
- preserve Step 20 independent replication as `REGISTERED_NOT_EXECUTED` until actually executed;
- verify that GitHub and Google Drive artifacts used by later stages are identified by exact link/version/hash where available.

**Exit rule:** governance roadmap and baseline are saved to both GitHub and Google Drive. No scientific step changes status merely because Stage 0 closes.

## Stage 2A — Blind Benchmark Packet Freeze

**Goal:** make the benchmark scientifically executable without answer leakage.

**Work:**
1. QA the fresh holdout-task table and scoring schema.
2. Confirm task coverage across CAM classification, assertion mapping, ICFR reasoning, accounting judgment, evidence retrieval, contradiction detection and explanation quality.
3. Freeze a common evidence packet and task order.
4. Keep the private gold key outside public GitHub.
5. Create a run manifest specifying model/version capture, timestamps, latency, tokens, price provenance and output-freeze rules.
6. Add leakage/adversarial checks and an explicit failure-preservation rule.

**Exit rule:** benchmark packet is frozen and auditable. Status remains `RESEARCH_PROTOTYPE` / `NOT_EXECUTED` until independent model runs occur.

## Stage 2B — Independent Blind Model Runs

**Goal:** obtain genuinely independent model outputs.

**Work:** invoke multiple independently selected models on the same frozen evidence packet and task order, without access to the gold key. Freeze raw responses before scoring.

**Required evidence:** provider/model/version, timestamp, prompt/evidence-packet version, raw response, latency, token counts, API/provider cost and pricing source.

**Exit rule:** only observed runs may be labelled executed. Missing providers, failed calls and refusals remain in the record.

## Stage 2C — Blinded Scoring & Contradiction Evaluation

**Goal:** score frozen outputs against the private gold key only after responses are locked.

**Work:** calculate correctness, grounding, contradiction handling and explanation-quality measures using the frozen rubric. Preserve per-task failures and disagreements rather than reporting only averages.

**Exit rule:** scoring is reproducible from frozen responses + scoring schema + gold key, with the gold key still kept private where required.

## Stage 2D — Cost per Verified Professional Output™

**Goal:** compute CVPO only from real prospective telemetry.

`CVPO = (AI/API cost + human verification cost + rework cost) / verified correct professional outputs`

**Work:** capture reviewer time, reviewer hourly cost assumption/source, rework cost, final verification outcome, latency and model/API cost.

**Exit rule:** publish a numeric CVPO only when real model and human-verification telemetry exist. Otherwise retain `NOT_EXECUTED`.

## Stage 2E — Phase 2 Closure & Dual Sync

**Goal:** create one reviewer-facing Phase 2 closure record.

**Required outputs:** benchmark results, failures/nulls, model-by-task detail, CVPO result or explicit non-result, source/version manifest, GitHub commit SHA, Drive links and cross-repository sync manifest.

**Promotion rule:** Phase 2 may close only on the evidence actually produced. Closure does not promote Phase 3 automatically.

## Stage 3A — Patent Entity Resolution & Source Freeze

Resolve canonical PatentsView/USPTO entities, subsidiaries and aliases for MSFT, WMT and JPM; freeze source release and access method; record blocked or ambiguous matches.

## Stage 3B — Aggregate Innovation Evidence

Only after Stage 3A: compute granted-patent counts, documented-window forward citations and CPC/technology diversity. Preserve `NOT_MEANINGFUL_FOR_CONSTRUCT` where cross-company comparison is not conceptually defensible.

## Stage 3C — Human–AI Study Scientific Readiness

Freeze T0–T3 preregistration, power analysis, instruments, consent/ethics dependencies and analysis plan. Participant outcomes remain `DESIGN_ONLY` until real participants are observed.

## Stage 3D — Digital Twin Integration

Integrate only evidence whose status and provenance are explicit. Synthetic management-accounting outputs remain `SYNTHETIC_EXECUTED`; public-source derived results remain separately labelled.

## Stage 3E — Phase 3 Closure & Dual Sync

Publish the executed/blocked/design-only state of each Stage 3 component without converting readiness into execution.

## Stage 4A — Human Gate™

Run professional review using only: `APPROVE / REVISE / REQUEST_MORE_EVIDENCE / REJECT / ESCALATE`. Existing MSFT bounded decision may be retained; WMT/JPM require explicit real reviewer decisions.

## Stage 4B — Independent Replication

A separate reviewer/environment executes the registered replication package. Step 20 stays `REGISTERED_NOT_EXECUTED` until this occurs for each company.

## Stage 4C — Final V1.3 Freeze

Freeze V1.3 only after prior gates are reviewed. Produce the final 60-state matrix, Evidence Passports, negative-evidence register, reproducibility manifest, GitHub/Drive synchronization record and final public/private patent-boundary review.

## Dual-Save Rule for Every Stage

For every completed work package:

1. **GitHub:** save reviewer-facing, reproducible, non-enabling public evidence in the V1.3 prototype directory.
2. **Google Drive:** save the corresponding research record; keep private gold keys, sensitive patent material and restricted evidence private.
3. Record exact filename, date, scientific status, source versions/hashes where available, GitHub commit SHA and Google Drive link.
4. Verify both copies before beginning the next work package.
5. Never overwrite failed or contradictory evidence; supersede it with an explicit reconciliation record.

## Execution order

`Stage 0 → 2A → 2B → 2C → 2D → 2E → 3A → 3B → 3C → 3D → 3E → 4A → 4B → 4C`

A blocked stage stops dependent downstream promotion but does not require deleting or hiding the blocked evidence.
