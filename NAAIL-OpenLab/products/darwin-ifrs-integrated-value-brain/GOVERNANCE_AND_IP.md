# Governance & IP Boundary

## Public specification rule

This folder is intentionally **non-enabling**.

Public content may include:

- product purpose;
- module names;
- architectural relationships;
- conceptual equations;
- public benchmark matrices;
- schema shapes;
- synthetic examples;
- governance principles.

Public content must not include:

- proprietary implementation algorithms;
- private prompts / system instructions;
- unreleased scoring weights;
- confidential benchmark labels;
- customer data;
- credentials / API keys;
- restricted model weights;
- patented or patent-sensitive implementation details;
- licensed IFRS standard text that cannot be redistributed;
- private POMELO / VERA implementation.

## Human accountability

The system must not independently authorize consequential financial actions unless the organization has explicitly configured a lawful, low-risk automation policy.

Material decisions must preserve:

- named human owner;
- approval tier;
- evidence trail;
- reasoning provenance;
- alternative comparison;
- override record;
- realized-outcome review.

## Internal Audit independence

Internal Audit is an assurance and challenge layer, not the business owner of the decision.

Management owns the decision.

Internal Audit assesses:

- evidence;
- controls;
- assumptions;
- model risk;
- compliance;
- governance;
- consistency of value claims.

## IFRS licensing

Commercial implementation should maintain a standards-content licensing review. Do not assume that public architectural references permit redistribution of IFRS copyrighted standard text.
