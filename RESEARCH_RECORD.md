## Archival / DOI policy

A DOI must never be fabricated. A DOI is added only after a legitimate archival deposit or DOI-minting release exists. Until then, cite the repository using project title, author, ORCID, version/release tag, date, and immutable commit hash.

Recommended archival sequence:

1. freeze a scientifically meaningful release;
2. create a GitHub tag/release;
3. ensure `CITATION.cff` matches the release version/date;
4. deposit/archive through an appropriate DOI-minting scholarly repository;
5. add the real DOI to `CITATION.cff`, README, and this research record;
6. link the archived release back to ORCID where supported.
