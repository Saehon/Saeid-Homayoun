# Master Scientific Discovery Architecture — Additive Integration

**Rule:** Preserve everything. Delete nothing. Existing repositories, registries, datasets, benchmarks, pilots, agents and documents remain intact. This architecture adds an organizing and control layer above them.

## 0. Existing Assets — Preserved

GitHub + Hugging Face + Kaggle + Google Drive + arXiv + Versioned Evidence Store + MLflow  
SEC/XBRL + PCAOB + AAER + CAM/KAM + ICFR + IFRS + ESG/VSME  
FT50/ABS4 replication registries + external-agent registries + Microsoft SEC/XBRL Pilot 001  
OpenAI + Anthropic/Claude + Google/Gemini + Microsoft + open-source agents.

No existing component is removed merely because a newer layer is introduced.

## 1. Systems Thinking Layer

Research Problem
→ system boundary
→ stakeholders
→ accounting/audit constructs
→ causal mechanisms
→ dependencies
→ feedback loops
→ risks/unintended consequences
→ measurable outcomes.

Purpose: start with the accounting/auditing problem rather than the technology.

## 2. Scientific Knowledge & Replication Layer

FT50/ABS4 theory and prior evidence
→ original paper
→ official/verified replication package
→ reproduce baseline
→ document deviations
→ preserve negative/failed replications.

arXiv is used for frontier discovery, not as a substitute for peer-reviewed theoretical positioning.

## 3. Co-Scientist Discovery Layer

For each research problem:
1. generate multiple competing hypotheses;
2. identify evidence that would support each;
3. identify evidence that would falsify each;
4. rank experiments by information value rather than desired result;
5. retain rejected hypotheses and negative findings.

Example ICFR competing explanations:
- genuine control weakness;
- firm complexity;
- disclosure-length artifact;
- industry effect;
- temporal leakage;
- outcome leakage;
- retrieval failure;
- model reasoning failure.

## 5. AlphaEvolve-Style Experiment Evolution

Maintain a candidate pool:
- deterministic/rule baseline;
- statistical/econometric baseline;
- ML baseline;
- transformer/NLP;
- RAG;
- GraphRAG;
- single agent;
- multi-agent;
- hybrid deterministic + ML + agent.

Evaluate candidates under a fixed, locked test design. Improve promising candidates while preventing benchmark leakage and adaptive overfitting.

Fitness dimensions:
predictive validity + calibration + evidence quality + robustness + reproducibility + interpretability + latency + cost.

## 6. FRANKENSTEIN Integration & Orchestration Layer

FRANKENSTEIN is the controlled integration layer, not the scientific method itself.

Evidence/Data
→ Versioned Evidence Store
→ Evidence Graph
→ provider adapters
→ OpenAI / Claude / Gemini / Microsoft / open-source agents
→ domain agents
→ evaluation
→ control gates.

Responsibilities:
- connect heterogeneous data/models/tools;
- enforce common input/output contracts;
- isolate provider-specific adapters;
- maintain evidence lineage;
- prevent one provider from receiving privileged evidence;
- route failures to challenge/falsification;
- preserve human authority.

## 8. Scientific Control & Falsification Layer

Deterministic Baseline
→ Data-quality checks
→ Evidence verification
→ Standards-as-Code where appropriate
→ Blind cross-agent challenge
→ Reviewer
→ Falsification Agent
→ independent replication
→ negative-result registry
→ Human Expert Gate.

Separate:

- retrieval errors;
- reasoning errors;
- standards errors;
- entity/time mismatch;

- model disagreement.

## 9. Human Approval Layer

Consequential accounting/audit conclusions remain human-approved.

Decision states:

REJECT
NEEDS_MORE_EVIDENCE
REPLICATE.

Record rationale, evidence reviewed and unresolved uncertainty.

## 13. Non-Deletion / Additive Governance Rule

1. Do not delete existing research artifacts.
2. Do not overwrite historical benchmark results to make new results look better.
3. Version superseded designs and retain provenance.
4. Add new adapters/modules rather than rewriting domain logic for each provider.
5. Preserve failed experiments and negative results.
6. Require explicit human authorization before destructive repository/data operations.
7. Treat the Master Architecture as an index/control layer over existing work.

## 14. Research Quality Gate

A study advances toward manuscript status only when:
Problem/construct defined
→ theory anchor verified
→ baseline reproduced
→ data provenance PASS
→ leakage/split checks PASS
→ identical-task comparison PASS
→ evidence verification PASS
→ falsification PASS
→ independent replication attempted
→ human validation PASS
→ limitations/negative results documented.
