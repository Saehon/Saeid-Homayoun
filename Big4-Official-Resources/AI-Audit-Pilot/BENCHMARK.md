# Big4 × AI-Enabled Audit — Pilot Benchmark

## Research question

How do the Big Four publicly describe the integration of AI into audit/assurance workflows, and which observable design dimensions can be translated into a provider-neutral research architecture?

## Evidence-based comparison

| Dimension | Deloitte | EY | KPMG | PwC |
|---|---|---|---|---|
| Agentic audit workflow | Explicit in Omnia | Explicit in EYQ Assurance Assistant / Canvas | Explicit in Clara AI | Selected source focuses primarily on assurance over AI |
| Large-scale / population analytics | Analytics embedded in Omnia | Explicit full-population analysis via Helix | Explicit population-level analysis | Not the central claim of selected source |
| Risk/anomaly focus | Explicit risk-factor analysis | Risk identification + analytics | Risk/anomaly analysis | AI governance/risk assessment |
| Evidence/reasoning trace | Evidence analysis/documentation described | Workflow/data integration described | Explicit documented agent reasoning/auditable trail | Independent assurance evidence/control assessment |
| Human professional gate | Explicit | Explicit | Explicit | Independent assurance/professional assessment |
| Assurance over AI itself | Not central to selected source | Not central to selected source | Not central to selected source | Explicit |

## Provider-neutral architecture derived from observable public patterns

Authorized evidence/data
→ risk & population analytics
→ specialized AI/agent tasks
→ evidence/reasoning trace
→ independent challenge / falsification
→ human professional approval
→ auditable output
→ feedback and controlled improvement

The independent falsification layer above is a research-design extension in this repository; it should not be represented as a feature of any Big Four platform unless a first-party source explicitly supports that statement.

## Candidate research variables

1. Agentic integration intensity.
2. Population-analytics coverage.
3. Evidence-traceability strength.
4. Human-oversight explicitness.
5. Risk/anomaly detection scope.
6. AI-assurance/governance coverage.

These variables can support future content analysis of dated public disclosures and, with appropriate outcome data, empirical tests involving audit quality, inspection outcomes, reporting timeliness, CAM/KAM characteristics, ICFR outcomes, or assurance scope.

## Next scientific gate

Before causal or performance claims, add independent outcome data (for example regulatory inspection data, SEC/PCAOB evidence, financial reporting outcomes, or validated experimental benchmarks). Vendor descriptions alone are evidence of disclosed architecture/positioning, not evidence that one firm's system performs better than another.
