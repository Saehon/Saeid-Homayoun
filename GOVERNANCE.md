# ECONOVA-S™ Governance

ECONOVA-S™ is a maintainer-led research-software and scientific-intelligence project.

## Maintainer

Primary maintainer and project owner: **Saeid Homayoun** (`@Saehon`).

The maintainer is responsible for:
- architectural consistency;
- scientific-governance rules;
- release approval;
- licensing and IP decisions;
- security and disclosure decisions;
- acceptance or rejection of external contributions;
- final interpretation of the Human Gate™.

## Architectural invariants

Unless explicitly changed by the project owner, ECONOVA-S preserves exactly two permanent cores:
1. Stable Economic Knowledge Core™
2. Replaceable Technology Core™

Evidence RAG, agent fabrics, model routers and orchestration layers are interfaces/capabilities rather than additional permanent cores.

## Scientific decision rights

Automated tests, LLM outputs, agent consensus, prediction accuracy and statistical significance do not constitute scientific approval. Scientific claims must satisfy the documented evidence gates and require explicit human judgment.

## Change classes

### Routine maintenance
Documentation, dependency updates, test improvements and non-semantic refactoring may be merged after review and automated checks.

### Scientific-method changes
Changes to constructs, estimands, identification logic, evidence classification, discovery thresholds, replication rules or welfare interpretation require explicit maintainer review and documented rationale.

### Architecture changes
Changes affecting the two-core model, Evidence Passport™, Human Gate™, licensing, IP policy or public scientific claims require explicit project-owner approval.

## Releases

Software versions use semantic versioning where practical. Architecture specification versions are tracked separately from software releases.

A public release should include:
- release notes;
- changelog update;
- passing tests;
- citation/version metadata;
- scientific-status statement;
- known limitations;
- license/IP review;
- reproducible artifact or archive where feasible.

## External contributions

External contributions are governed by `CONTRIBUTING.md`. Merge approval does not automatically confer authorship, scientific endorsement, commercial rights or ownership rights beyond written agreements.

## Transparency

Material scientific limitations, unresolved validation failures and rejected discovery claims should remain visible rather than being silently removed to improve presentation.
