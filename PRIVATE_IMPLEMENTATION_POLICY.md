# ECONOVA-S™ Public / Private Implementation Policy

## Public repository

The public ECONOVA-S™ repository is intended to establish authorship, scientific positioning, citation, high-level architecture, research protocols, selected reproducible demonstrations, and non-confidential examples.

## Keep private by default

The following should remain in private repositories or controlled storage unless specifically approved for public release:

- production source code and deployment infrastructure;
- proprietary orchestration and routing logic;
- unpublished algorithms or technical implementations under patent review;
- commercial evaluation datasets and benchmark suites;
- private prompts, system policies, secrets, tokens, credentials, and connector configurations;
- customer, partner, client, or licensed data;
- proprietary economic scoring rules or commercial calibration parameters;
- security architecture and exploit-sensitive implementation details;
- unreleased product roadmaps, pricing, commercial agreements, and license negotiations;
- invention disclosures and patent drafts.

## Publication gate

Before moving material from private to public, review:

1. copyright ownership;
2. third-party licenses;
3. confidentiality obligations;
4. patent/public-disclosure risk;
5. personal or sensitive data;
6. security implications;
7. commercial value;
8. scientific reproducibility needs.

Only material that passes this gate should be committed to the public repository.

## Recommended repository split

**Public:** `Saehon/Saeid-Homayoun` — architecture, citation, papers, safe examples, reproducibility interfaces.

**Private:** a dedicated ECONOVA-S implementation repository — production code, technical inventions, private benchmarks, deployment, commercial modules, and confidential research assets.

## Governing principle

> Publish enough to establish scholarship and reproducibility; retain enough to preserve security, commercial value, confidentiality, and future IP options.
